- 2026-11-12 [R] R2 data regenerated after a review of the first full run: 391/404 Banglish replies drifted into Hindi ("aapke ... gaya"), Hindi/Bengali used wrong words for "dispute" (बहस / बर्बरता / অপরাধ), some replies dropped the BLK/DSP reference. - 2026-11-12 [R] Test split = up to 30 per (lang, category) cell but never more than 1/3 of a cell, so ~490 episodes instead of 600. Why: no_tool / clarify / multi_tool cells are small (45-90 per language) and multi-tool is the scarcest training signal. Dedup (CuratorKIT exact + MinHash 0.85, digits masked) runs inside each (lang, category) before splitting.
- 2026-11-12 [R] Quality filter: CuratorKIT RewardGate with 0-1 scores from Qwen3-14B was uncalibrated (98% scored 0.2-0.4, even clean English), so the judge became a yes/no checklist (garbled / wrong language / wrong fact / incomplete / wrong voice / nonsense customer message). Precise but low recall: it catches skipped facts and echoes, not garbled Banglish/Hinglish words (the same model wrote them). Flagged rows are dropped from train/val (88). Remaining code-mixed wording noise is a known limitation.
- 2026-11-12 [R] Test-set review was done by the R agent (Claude), not by a human (R's human delegated it): all 46 judge-flagged test episodes plus a 60-episode random sample were read. Rule: reject only when the customer message is garbled or does not match the gold calls, since metrics score tool calls and not reply wording. 8 rejected (`data/spotcheck_rejected.txt`). Final: 1937 train / 99 val / 486 test, zero id or customer-message overlap. Write-up must say "agent-reviewed", not "human-checked".
- 2026-11-12 [F] Precision: bf16 only on GPUs with bf16 hardware (compute capability >= 8), fp16 everywhere else (`train.policy.native_bf16`). Why: `torch.cuda.is_bf16_supported()` is True on T4 through emulation. The profiler showed 84% of GPU time in `magma_sgemmEx<float, bf16>`. In fp16 on Kaggle T4x2, train goes 7.8 -> 1.86 s/episode and val 300 -> 64 s, and the loss curve matches the bf16 run. The full F3 run takes ~2.2 h instead of ~9 h.
- 2026-11-12 [F] F5 (GRPO) closed as no-go, by measurement. Probe (`scripts/train_grpo_probe.py`, results in ToolW/desi-agent-training-logs runs/grpo-probe): with the final SFT adapter, 8 first turns sampled at T=1.0 for each of 377 train prompts in the SFT error areas (230 clarify + 147 single block_card), scored with `api.reward` through `fmt.run_episode` (`train/grpo.py`). 95.7% of samples succeed, only 12.7% of prompts show any reward variance (mostly 1 slip in 8), 1 prompt fails on all 8. Why: GRPO learns only from reward differences within a prompt's group, so there is almost no gradient, and what there is comes from temperature noise that greedy decoding already avoids. The risk of degrading a 97.7% model outweighs the possible gain. Revisit only if the OOD set shows a real drop in clarify/block_card.
